# Тесты и тир-листы — Google Authentication + Firestore

Подготовлено в ветке `feature/firebase-auth-firestore`; опубликованная ветка `main` пока не изменена. Подключён существующий Firebase проект `igatrackers`. Публичная конфигурация лежит в `firebase-config.js`. Загрузка файлов и Firebase Storage **не используются**; изображения указываются по внешним URL.

## Обязательный шаг в Firebase Console (общий проект с другими сайтами)

Открой [Firebase Console](https://console.firebase.google.com/project/igatrackers/firestore/rules) → Firestore Database → Rules. **Сохрани копию действующих правил. Не заменяй их содержимым файла с правилами тестов!** Внутрь уже существующего блока `match /databases/{database}/documents` добавь только фрагмент из [firestore-rules-snippet.txt](./firestore-rules-snippet.txt) и нажми Publish. Это сохраняет правила остальных приложений неизменными, но обрати внимание: если там есть разрешающие широкие правила `match /{document=**}`, они также могут распространяться на новые пути; правила Firestore объединяются по принципу OR.

Новое приложение использует только `testAppUsers/{uid}/tests/{testId}`, `testAppUsers/{uid}/results/{testId}`, `testAppUsers/{uid}/progress/{testId}`. Другие коллекции не читаются и не изменяются. В Authentication → Sign-in method должен быть включён Google, а в Authorized domains указан `iga0077.github.io` (пользователь подтвердил, что уже настроено).

## Подключение к сайту

После публикации правил проверь изменения в [Pull Request #1](https://github.com/iga0077/test/pull/1), затем объедини в `main`. GitHub Pages раздаёт сайт по адресу https://iga0077.github.io/test/ . Работает без npm/сборки, через браузерный Firebase SDK.

## Перенос сохранённых локальных данных

В главном меню после входа через Google находятся кнопки **«Экспорт»** и **«Импорт»**. Импорт принимает исходный JSON формата `pairwise-tests-backup` версии 1 из локальной версии: `tests`, `results`, `progress`. Прежний файл не изменяется. Сначала экспортируй имеющиеся облачные данные, если они есть: импорт **полностью заменяет** набор тестов, результатов и черновиков текущего пользователя. Для сохранности импорт проводится одним атомарным пакетом: при ошибке размера, прав или сети пакет не должен частично перезаписывать документы.

Каждый документ Firestore ограничен 1 МиБ; для запаса приложение отклоняет JSON-документы больше 900 КБ, а также резервные копии, превышающие безопасные пределы одного пакета (400 операций, суммарно 8 МБ). Если старый экспорт содержит крупные картинки, встроенные как `data:image/...`, импорт **сообщит об ошибке, а не удалит их молча**. Укажи для таких картинок внешние URL в локальной версии, сделай новый экспорт и повтори импорт. Обычные внешние URL сохраняются без изменений.

Экспорт создаёт JSON той же версии со всеми тремя разделами. После каждого изменения показывается статус сохранения; не закрывай страницу при записи. Если сохранение закончилось ошибкой, текущая вкладка может содержать изменения, отсутствующие в облаке — сохрани JSON-экспорт только после успешной записи.

Прямой доступ к чужим данным ограничен новым правилом; оно не заменяет аудит уже существующих широких правил в общем Firebase проекте.
