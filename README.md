# Тесты и тир-листы — Firebase версия

Ветка `feature/firebase-auth-firestore` добавляет Google Authentication и облачные данные Firestore. Публикуемую ветку `main` не меняли.

## Настройка Firebase

1. Открой [Firebase Console](https://console.firebase.google.com/) и создай проект (или выбери свой).
2. Project settings → Your apps → Add app → Web (`</>`). Скопируй объект `firebaseConfig` в `firebase-config.js`. Поля `apiKey`, `authDomain`, `projectId`, `appId` обязательны; `storageBucket` нужен для файлов с компьютера. Это публичная конфигурация веб-приложения, а не секретный ключ сервера.
3. Authentication → Sign-in method → Google → Enable. Укажи почту поддержки, сохрани.
4. Authentication → Settings → Authorized domains → добавь `iga0077.github.io` (без `https://` и `/test/`). Для проверки на `localhost` добавь его отдельно при необходимости.
5. Firestore Database → Create database. Выбери регион осознанно: после создания его обычно нельзя поменять. Открой вкладку Rules, вставь содержимое `firestore.rules`, нажми Publish. **Не используй test mode или правила `allow read, write: if true` на опубликованном сайте.**
6. Необязательно: Storage → Get started, выбери bucket. Укажи полученный `storageBucket` в конфиге и опубликуй `storage.rules` в Storage → Rules. Cloud Storage для новых проектов требует Blaze (подключение биллинга); без Storage используй ссылки на изображения. **Не вставляй в репозиторий service account JSON или другие секретные ключи.**
7. После настройки можно объединить эту ветку с `main` (или открыть на время отдельную тестовую публикацию). GitHub Pages: Settings → Pages → Deploy from a branch → main → /(root).

## Что сохраняется

`users/{uid}/tests/{testId}` — тест и варианты; `users/{uid}/results/{testId}` — результаты сравнений и тир-листы; `users/{uid}/progress/{testId}` — черновики. Google Authentication определяет `uid`, Firestore Rules разрешают доступ только владельцу. Чужие записи не загружаются.

В отличие от прежней версии, данные не записываются в `localStorage`. Старые записи остаются в браузере нетронутыми. После входа нажми «Импортировать данные из этого браузера», чтобы перенести в свой аккаунт тесты, которых ещё нет в облаке, вместе с результатами и прогрессом. Для старых изображений формата data URL нужен настроенный Storage. Импорт не удаляет локальную копию.

Изображения с компьютера загружаются в Storage (до 1,5 МБ, JPG/PNG/WebP/GIF), в Firestore сохраняются ссылки; внешние URL работают без Storage. Firestore ограничивает размер одного документа 1 МиБ, поэтому очень длинные тесты могут потребовать отдельного разбиения на документы.

Статус сохранения показан вверху страницы. Для прогресса сравнения выполняется запись после каждого выбора. Не закрывай страницу при статусе «Сохраняем изменения» и проверяй сообщения об ошибках. Если браузер не в сети, загрузка и сохранение без дополнительного offline-cache не гарантируются.
